WANES ride-matching platform

From → To.
A ride, either way.

A rider asks for a trip between two addresses. Wanes instantly shows trips drivers already posted along that route — and when nothing fits, it pings nearby drivers to come get them.

instant
Mode 1 · Carpool

Show posted trips

Match the rider to trips drivers already planned along the same route and time window. Like BlaBlaCar — browse, pick, book a seat.

on-demand
Mode 2 · Hail

Notify nearby drivers

No match? Open a ride request and push it to online drivers within radius. First to accept wins — like inDrive / Uber.

How a search works

One search, two possible outcomes

1
Rider enters From → To, when, and seats.

Both addresses are geocoded to coordinates.

2
Match engine filters driver trips near the route within the time window, with seats free.

PostGIS finds trips whose route passes close to both pickup and drop-off, in the right direction.

3a
Matches found → ranked list, rider picks and books a seat.
3b
No match → a ride request is opened and pushed to nearby drivers; radius widens until someone accepts.

The match engine · core IP

Candidates are filtered cheaply, then scored

Step one throws away everything impossible using indexed geo + time filters. Step two ranks what survives so the rider sees the best rides first.

score =
w₁· 1 / detour_distancehow little the driver detours
w₂· 1 / pickup_distancehow near the route passes pickup
w₃· 1 / time_gapcloseness to requested time
w₄· driver_ratingtrust
− w₅· price_per_seatcheaper ranks higher

Roadmap

Ship a demoable product by Phase 1

Phase 0

Foundations + profile

Repo, Docker (Postgres + PostGIS + Redis), API skeleton, users, auth & full profile.

Phase 1

Posted trips + search

Drivers post trips; riders search and book a seat. Simple straight-line matching.

◆ First demoable product
Phase 2

On-demand fallback

Ride requests, live driver location, notify-nearby + accept flow.

Phase 3

Route-aware matching

PostGIS route geometry, detour scoring, real ranking.

Phase 4

Polish & scale

Ratings, driver verification, admin dashboard, mobile app. Payments deferred — not now.

Decisions to lock before we scaffold:
  • Maps provider — Mapbox (cheaper) vs Google (coverage)?
  • First city / country — affects maps, regulation.
  • Show a driver-set price as info only, or hide price for now?
  • Driver verification — manual admin review or automated?
  • Language — Arabic + English / RTL?

Note: Payments are deferred — no wallet or gateway in the current scope. Trips are arranged in-app; any settlement is offline/cash for now.
